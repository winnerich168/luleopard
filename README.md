## 快速開始

**想直接上線給人用 → 看 [`DEPLOY.md`](DEPLOY.md)**（GitHub Pages 約 10 分鐘，全程免費）。

先在自己電腦上試跑：

1. 把 `luleopard.html` 放到手機上（或丟到任何靜態網站空間），用瀏覽器打開。
2. 按 **「開始導航警示」** → 允許定位權限。這個按鈕同時會解鎖語音播報（iOS / Android 都要求語音必須由使用者手勢啟動，這是瀏覽器規定，繞不過）。
3. 想先確認警示會不會動：**設定 → 模擬行車 → 開始模擬行車**。它會沿著資料庫中最密集的一段路自動行駛，實際觸發語音、嗶聲與震動。

> ⚠️ **定位權限需要 HTTPS。** 直接用 `file://` 開啟或用 http 連線時，多數瀏覽器會拒絕 GPS。正式使用請放上 HTTPS 網址（GitHub Pages、Netlify、Cloudflare Pages 都免費且夠用）。

## 點位資料怎麼補齊（重要）

內建的 138 點只是**示範**，來自警政署那份縣道資料的宜蘭＋新竹。真正在路上要用，必須自己補三塊：

| 缺什麼 | 去哪拿 | 備註 |
|---|---|---|
| ~~國道~~ | ~~[國道公路固定式測速照相地點](https://data.gov.tw/dataset/13940)~~ | ✅ **已內建 176 點**，不用另外匯入 |
| **六都** | 各市自己的開放平臺（App 資料頁已列出六個入口） | 全國那份**不含六都**，這是最大的坑 |
| **其餘各縣** | [測速執法設置點](https://data.gov.tw/dataset/7320) | 省道／縣道／地方道路，UTF-8 CSV |
| **離島** | [澎湖 CKAN](https://opendata.penghu.gov.tw/dataset/pb140320-2022-07-14-1657785496)（金門已在上面那份裡） | 馬祖目前沒有機器可讀來源 |

### 來源是累加的

匯入不會覆蓋。國道匯一份、台北匯一份、高雄匯一份，全部疊加成一個資料庫，**座標重複的自動去重**；「資料」頁會列出每個來源與點數，可以個別移除。同名來源再匯入一次會就地取代，方便日後更新。

匯入支援：CSV（自動判讀 UTF-8 / Big5）、ZIP（自動解壓，會掃描壓縮檔內所有 CSV/JSON）、GeoJSON、JSON。欄位名稱也自動判讀 —— 國道那份用「座標緯度／座標經度／設置地點／拍攝方向」，縣市那份用「Latitude／Longitude／Address／direct」，兩種都吃得下。取締項目寫「區間超速」的會自動標記成區間測速。

### 更好的做法：自建資料源（已附腳本）

`etl/` 資料夾裡有一支 `build_speedcams.py`，把所有來源抓下來、正規化、跨來源去重，輸出一份合併好的檔案。搭配附的 GitHub Actions，每週自動更新並發布到 GitHub Pages；**GitHub Pages 帶 `Access-Control-Allow-Origin: *`，所以 App 可以直接 fetch，CORS 問題就繞過去了**。

設定一次之後，使用者完全不用手動下載匯入：

1. 把 `etl/` 和 `.github/` 放進一個 GitHub repo，開啟 Pages（來源選 GitHub Actions）
2. App「資料」頁 →「我的資料源」填入 `https://<帳號>.github.io/<專案>/data/speedcams.min.json`
3. 按「從資料源更新」；開啟「開啟時自動更新」後每天自動抓一次

抓失敗會保留上次成功的資料，不影響離線使用。細節看 [`etl/README.md`](etl/README.md)。

### 為什麼 App 內的「直接抓取」常常失敗

App 內有「直接抓取」按鈕，但**政府網站多半沒開 CORS 標頭**，瀏覽器直接抓通常被擋（國道那份的 tgos.tw 還會直接回 403）。實務上三條路：

1. **手動下載後匯入**（現在就能用，一次搞定）
2. **自建後端代理**（正式版建議）：一支小 API 定期抓取各來源、合併去重、輸出一份 GeoJSON 給前端，順便解決更新問題
3. **包成 App 之後**：原生 WebView 沒有 CORS 限制，可以直接抓

## 掉落物與路況回報

### 兩種標示方式，都是設計給乘客／副駕操作的

**① 公里樁號**（高速公路最快最準）

高速公路旁每 100 公尺就有一支里程牌，乘客抬頭就看得到 —— 比在行進中拖地圖精準得多，也安全得多。

- App 會先**自動推估**目前樁號：從已匯入的國道測速點名稱（「國道1號南下 47.5K」）萃取出樁號錨點，配合 GPS 推算
- 看到路邊里程牌時按一下**「校正為現在位置」**輸入實際數字，之後就靠 GPS 里程自動跟著車推進（±50 公尺）
- 下方列出**前後一分鐘內**會經過的樁號（往後 0.5 km、往前依車速約 1–3 km，0.1 km 一格），直接點掉落物所在的那個
- 台灣國道與快速道路的里程都是由北往南遞增，所以南下＝里程增加、北上＝遞減，App 會依你的航向自動判斷

**② 照片**

乘客拍下掉落物後選那張照片，App 只讀取 EXIF 裡拍攝當下的經緯度來定位，**照片本身不會被保存或上傳**。

> 注意：手機相機要開啟定位權限才會寫入座標；經 LINE 或社群 App 轉傳過的照片 EXIF 會被移除。

**③ 一鍵通報**（給駕駛的唯一操作）

地圖頁右下角有**兩顆大按鈕**，按一下立刻通報，**6 秒內可以按「復原」**：

| 按鈕 | 位置 | 大小 | 顏色 |
|---|---|---|---|
| 📦 **掉落物** | 最下面 | 84 px | 橘 |
| 🚨 **事故** | 上面一點 | 70 px | 正紅 |
| ⋯ 其他類型 | 最上面 | 46 px | 深灰 |

「⋯」展開的選單**6 秒沒選就自動收起**（上緣有倒數條），碰到選單會重新計時，點畫面其他地方或切換分頁也會收起 —— 開著卻沒選等於擋住地圖。

掉落物最常遇到，所以放在最下面（拇指最好搆到）而且最大；事故比較少見但更緊急，用正紅色與不同尺寸區分 —— **開車時不用低頭看也摸得出來按到哪一顆**。「⋯」展開其餘七種類型（車輛故障、塞車、施工、路面坑洞、積水、動物、臨檢）。

因為掉落物通常是「剛剛」經過的，一鍵通報會把位置往回退約 2.5 秒車程（時速 100 約 70 公尺），比標在按下去的當下更接近實際位置。

### 警示距離

| 道路類別 | 預告 | 注意 | 警告 |
|---|---|---|---|
| 國道 / 高架 / 快速道路（含西濱台61） | 車速 × 90 秒<br>下限 1.5 km、上限 5 km | × 45 秒 | × 15 秒 |
| 一般道路 | 500 m 起 | 250 m | 100 m |

用「反應時間」而不是固定公里數，是因為時速 110 和塞在車陣裡需要的提前量差很多。實測：時速 100 → 2.5 公里外開始提醒；塞車（時速 20）→ 縮到下限 1.5 公里；時速 45 的一般道路 → 剛好 500 公尺。

和測速照相一樣三級遞減，語音會唸出樁號與車道：

```
前方2.5公里，注意掉落物，國道1號 47.5公里處
注意，1.2公里有掉落物，外側車道
掉落物就在前方，外側車道，請小心
```

對向車道的事件不會誤報（用回報當下的方位角比對，超過 70° 視為對向），已經開過去的也不會重報。

### 共享給附近的人

回報只存自己手機是沒有意義的。`backend/` 內有一支現成的 **Cloudflare Worker**，免費方案就能跑：

```bash
cd backend
npx wrangler kv namespace create HAZARDS   # 把 id 填進 wrangler.toml
npx wrangler deploy
```

拿到網址後填進 App 的「回報 → 共享回報」。之後你的回報會自動上傳，App 每 3 分鐘拉一次周邊 15 公里的他人回報。

後端會自動處理：依類型過期（掉落物 2 小時、施工 12 小時、坑洞 24 小時…）、150 公尺內同類自動併成「確認」而不是長出重複圖示、兩個人說「已清除」就消失、同裝置 20 秒冷卻防灌水。**不存照片、不存帳號、不存軌跡。** 細節看 [`backend/README.md`](backend/README.md)。

## 路況資料

### TDX（即時、官方、免費）
到 [tdx.transportdata.tw](https://tdx.transportdata.tw/) 註冊會員，取得 Client ID / Secret，填進 App 的「資料」頁即可。

- Token 端點：`https://tdx.transportdata.tw/auth/realms/TDXConnect/protocol/openid-connect/token`（POST，`grant_type=client_credentials`）
- Token 有效 24 小時；Token 端點每 IP 每分鐘限 20 次
- 事件／路況 API 路徑可在 App 內自行修改，實際可用路徑請對照 [TDX Swagger](https://tdx.transportdata.tw/api-service/swagger)
- 一樣可能遇到 CORS，正式版建議由自己的後端代打

### 中廣 / 警廣
**廣播內容沒有公開 API。** 這點必須誠實說：沒辦法自動抓。目前的做法是「路況」頁提供手動輸入欄位，聽到播報時記一筆。長期解法有兩條：

- 走 **1968 / TDX 的官方事件資料**，涵蓋率其實比廣播高，而且結構化
- 做**使用者回報**（類似 Waze），累積夠多使用者後才會有價值，初期會很空

### 關於神盾 App
你提到想從神盾抓現成的警示點。這條路我不建議走：抓取別家 App 的資料庫幾乎一定違反其使用條款，資料本身也可能受保護，如果之後想上架或商業化，風險很高。好消息是**神盾的固定式測速點來源本來就是同一份政府開放資料**，直接用官方來源就好，還能合法標示授權。真正需要靠社群累積的是「臨檢、移動式測速、即時事故」——那部分用你自己的使用者回報功能長出來會更乾淨。

## 路網幾何：讓計算貼著路走

沒有路網時，「前方測速點」只能用航向 ±35° 的錐形判斷。**彎道會失效。**

實測一段 S 形山路：

| | 錐形判斷 | 貼路計算 |
|---|---|---|
| 找到前方測速點 | **0 個**（漏掉了） | 正確找到 2.02 公里外那一個 |
| 同一段路的距離 | 直線 4 835 m | 沿路 7 908 m |

**直線低估了 39%** —— 樁號推算會整整差 3 公里。

`etl/build_roadnet.py` 從 OpenStreetMap 抓國道與快速道路中心線，把散落的幾百個 way 接成連續路線、簡化後輸出。App 在「資料 → 路網幾何」載入即可。載入後：

- 前方測速點**沿著道路**往前找，彎道跟得上，距離是沿路距離
- 樁號推算改用沿路距離，山區誤差大幅下降（顯示會變成「±30m（沿路計算）」）
- 貼在別條路上的測速點會被排除，不會把隔壁道路的點算進來

**沒載入完全不影響其他功能** —— 所有計算自動退回原本的直線／錐形做法，已驗證。

> ⚠️ OpenStreetMap 是 **ODbL** 授權，和政府開放資料不同：必須標示 "© OpenStreetMap contributors"，衍生資料庫要以相同方式分享。上架前請確認。

## 靜止自動省電

背景定位很吃電。停紅燈、休息站、到家忘了關 —— 這些情況沒必要維持 8 公尺一次的高頻定位。

靜止超過設定時間（預設 5 分鐘）就：

- 原生版把 `distanceFilter` 從 8 公尺拉到 250 公尺，通知文字改成「省電待命」
- 放掉螢幕常亮鎖
- 跳過畫面重繪
- **重新註冊 watcher 時不會再跳權限對話框**

偵測到時速 > 4 或離開錨點 80 公尺就立刻恢復完整警示。判定同時看速度與位移，所以 GPS 飄移不會誤判成在移動。

## 臺南：把沒有座標的資料補回來

臺南市的測速開放資料**沒有經緯度欄位**，只有「民族路二段與西門路口」這種文字，所以原本整份會被丟掉。

`etl/geocode_tainan.py` 用兩種策略補：**路口交會點**（用 Overpass 找同時屬於兩條路的節點 —— 測速點本來就設在路口，所以這比一般地址查詢準得多），查不到才退回 **Nominatim 全文查詢**。

輸出的 CSV 直接餵給 `build_speedcams.py`，並在 `sources.json` 裡把 priority 設成 8（很低）——**官方有座標時一律以官方為準**，這份只補空缺。每一筆都標記 `geocode_method` 可以追溯。

> ⚠️ **這些座標是推算的，不是官方公布值。**

## 旅程與區間測速

新增的「🚗 旅程」分頁。這一頁的重點不是列清單，而是**區間測速**。

### 為什麼區間測速要特別做

點式測速照相只要通過那一瞬間不超速就好，所以提示位置就夠了。**區間測速抓的是整段的平均速度** —— 你在入口看到警示、乖乖降速，然後在區間內狂飆，出口一樣被開單。所以真正要算的是：

- **你進入區間到現在的平均時速**是多少
- **剩下這段最高可以跑多快**，才不會讓整段平均超過速限

App 進入區間後就開始算，HUD 頂端會常駐一條：

```
📏 區間測速 速限60　剩 1.1 km　可跑 46          85
```

平均超過速限時整條轉紅並語音提醒一次。**放慢真的救得回來** —— 測試中前半段用時速 90 衝，中途平均 90（已超速），剩下 1.1 公里降到 30，最終平均 47，判定未超速。這正是區間測速跟點式測速最大的差別，App 會把這件事講清楚。

### 起訖里程從哪來

開放資料的名稱裡就有，只是格式很亂：

| 名稱 | 解析結果 |
|---|---|
| `台9線68k+600m至56k+600m` | 68.6K → 56.6K，全長 12 公里 |
| `台3線82.2公里至84.3公里` | 82.2K → 84.3K，2.1 公里 |
| `台9線129k+404m至136k+883m(觀音隧道)` | 7.5 公里 |
| `南澳鄉台9線110k+960m至蘇澳鎮台9線108k+224m(東澳隧道)` | 2.7 公里（中間夾了路名也吃得下） |
| `台15線鳳鼻隧道` | **沒寫範圍** → 只算平均，不算剩餘距離 |

內建的 6 個區間有 5 個解析出長度，另外 132 個一般測速點**沒有任何一個被誤判成區間**。

### 這一頁還有

- **前方測速點**：航向 ±35° 走廊內、20 公里以內，只列與行進方向相符的（對向和已經過的不會出現），區間測速另外標示全長
- **已經過**：記下通過每個點時的**實際車速**與有沒有超速，開完一趟可以回頭看自己在哪裡踩太快
- **旅程統計**：里程、時間、行駛平均、最高時速、經過幾個測速點、其中超速幾次

## 幾個人回報過（可信度）

一件事被幾個人看到，是判斷該不該相信它的最重要訊號。後端把「第一個回報的人 + 後續確認的人」加總成 `reports`，App 到處都顯示：

- **清單**：`📦 掉落物 3 人回報 · 外側車道`，人數越多徽章顏色越熱（藍 → 橘 → 紅），排序也優先
- **地圖**：圖示右上角掛紅色數字，人數多的圖示本身也放大（22 → 27 → 32 px），一眼看得出哪個比較可信
- **警示列**：`掉落物 · 4人回報 · 外側車道 · 國1 47.5K`
- **語音**：兩人以上就唸出來 ——「前方2.5公里，**4人回報**，注意掉落物」。開車時聽到有人數，比較敢相信

人數也會影響**警示優先順序**：同一個距離級距內，先比嚴重度，再比回報人數，最後才比距離。

### 怎麼累積

| 情境 | 結果 |
|---|---|
| 你在別人回報過的地方再回報一次（150 m 內、同類、同方向） | 後端自動併成確認，人數 +1，**不會長出重複圖示** |
| 別人的回報，你按「👀 我也看到了」 | 人數 +1，並延長存活時間（東西還在，警示就繼續） |
| 按「✅ 已經清掉了」 | 累積 2 票就從所有人的清單消失 |

沒設定後端時這些操作只作用在本機，App 會明講。

## 過期回報怎麼自動下架（v1.1）

這是整個回報系統最要命的問題：**10:00 有人回報國3南下 134.3K 內側事故，10:35 已經排除了，但沒有人去按取消，於是它會一直報。** 報幾次之後使用者就不信任這個 App 了。

「找人顧後台」不是解法 —— 沒有人 24 小時盯著全台灣。所以做了**四道自動化防線**，每一道都不需要任何人介入：

### 第 1 道：回報的人自己撤銷（唯一需要按的，但只有按錯的人才要按）

自己回報的事件，清單上會多一顆 **`↩︎ 撤銷（我按錯了）`**。按下去就從後端直接刪掉，不用等投票、不用等衰減。

後端用裝置代碼驗證 —— **別人的回報看不到這顆鈕**，硬打 API 也會被擋（403）。否則一個人就能把全台灣的回報都刪光。

### 第 2 道：被動車流探針（最重要，使用者完全不用按）

你只要**開過去**，App 就會替所有人驗證這件事還在不在：

1. 平常持續記錄你自己最近 2 分鐘的巡航速度中位數，當作**基準**
2. 進入事件 250 m 內時，記下基準，並追蹤通過期間的最低速
3. 離開 450 m 後判定：
   - 掉速 **≥ 35 %** → 東西還在 → 送 `slowed=true`，事件分數 ×1.18
   - 掉速 **≤ 15 %** → 已經排除了 → 送 `slowed=false`，事件分數 ×0.72
   - 中間 → 不表態

幾個刻意的設計：

- **跟你自己的基準比，不是跟速限比**。塞車時大家都慢，跟速限比會全部誤判成「有事」。
- **基準本來就低於 25 km/h 就整筆放棄**（你本來就在塞車，通過事件也慢，看不出差別）。
- **基準只在還沒進入觀察範圍時累積**，否則會被事件本身造成的車陣拉低，變成「基準也慢、通過也慢 → 判定沒事」的假陰性。這是實際測出來的 bug，已修。
- **上傳內容只有 `{事件座標, slowed}` 三個欄位** —— 不送你的速度、不送你的座標、不送裝置代碼。後端連「誰經過了」都不知道。
- 可以在設定裡整個關掉。

實際效果：**3~4 台車開過去沒減速，20 分鐘內就會自動下架**，比自然衰減快一倍。

### 第 3 道：置信度衰減（沒人經過也會自己過期）

每一種事件有自己的**半衰期**，因為它們的壽命本來就不一樣：

| 類型 | 半衰期 | 為什麼 |
|---|---|---|
| 塞車 | 15 分 | 變化最快 |
| 車輛故障、動物 | 20 分 | 拖吊／跑掉就沒了 |
| 事故 | 25 分 | 一般事故約 30 分內排除 |
| 掉落物 | 45 分 | 要等清潔隊 |
| 臨檢 | 60 分 | 一個班次 |
| 積水 | 3 小時 | 要等退水 |
| 施工 | 4 小時 | 通常整個工班 |
| 路面坑洞 | 12 小時 | 要等養護單位 |

分數 = `(2 + 確認人數) × 0.5^(年齡/半衰期) × 0.72^(沒減速探針) × 1.18^(有減速探針)`

兩個門檻：

- **分數 ≥ 1.0 才出聲**
- **分數 ≥ 0.4 才顯示**（低於就從所有人的清單消失）

用你舉的那個例子實際跑出來：

| 時間 | 分數 | 行為 |
|---|---|---|
| 10:00 剛回報 | 2.00 | 🔊 語音 +地圖 +清單 |
| 10:25 | 1.00 | 🔊 還是會報 |
| **10:35** | **0.76** | **🔇 不出聲了**，清單淡色顯示「事故（待確認）」 |
| 11:00 | 0.38 | ❌ 完全消失 |
| 10:35 且 3 台車沒減速 | 0.28 | ❌ 提早消失 |
| 10:35 但 3 個人確認過 | 1.89 | 🔊 繼續報（真的還在的話） |

也就是說**你舉的那個沒人取消的事故，35 分鐘就自動閉嘴、1 小時自動消失**，就算完全沒有第二台車經過。

### 第 4 道：跟官方事件對帳（TDX / 1968）

後端每 10 分鐘跑一次 cron，抓 TDX 的即時事件（1968 的資料就是走 TDX 出來的）：

- 官方事件 **500 m 內 + 同類型 + 方向夾角 ≤ 90°** → 視為同一件事
- 官方標記 **已結束** → **直接刪掉**對應的使用者回報
- 官方標記 **進行中** → 分數給一個 **1.2 的下限**，不讓它因為衰減提早消失

這一道是「官方說了算」，所以優先於前三道。設定 TDX 金鑰就會自動運作：

```bash
npx wrangler secret put TDX_ID
npx wrangler secret put TDX_SECRET
```

沒設金鑰時 cron 會明確略過（不會爆炸），前三道照常運作。

> 為什麼不直接用 1968 就好？因為 1968 只有**官方通報**的事故與施工，路上的掉落物、坑洞、臨檢它沒有 —— 那些正是使用者回報最有價值的部分。所以是**官方資料當校正，使用者回報當主體**。

## 背景定位（打包成 App）

網頁版最大的缺口是**關螢幕就停止警示**。對測速照相只是不方便；對掉落物是致命的 —— 你正在高速公路上，手機多半在充電座上熄屏。

`mobile/` 是一個現成的 Capacitor 專案：

```bash
cd mobile
npm install
npm run add:android      # 或 npm run add:ios
npm run android          # 開啟 Android Studio
```

**前端完全不用改寫。** `luleopard.html` 內建橋接層：偵測到 `window.Capacitor` 就自動改用背景定位與原生 TTS，在一般瀏覽器裡整段不啟用。改完 HTML 後跑 `npm run sync` 即可。

兩個容易漏掉、漏了就白做的設定：

- Android 要在 Manifest 宣告 `ACCESS_BACKGROUND_LOCATION` 與 `foregroundServiceType="location"` 的 Service
- iOS 的 `UIBackgroundModes` 除了 `location` **還要加 `audio`** —— 沒有它，背景定位會動但語音發不出聲音

完整的權限片段、送審注意事項與耗電考量都在 [`mobile/README.md`](mobile/README.md)。

## 之後包成 App

前端不用重寫，用 [Capacitor](https://capacitorjs.com/) 直接包：

```bash
npm init -y && npm i @capacitor/core @capacitor/cli
npx cap init 鹿豹 tw.luleopard.app
mkdir -p www && cp luleopard.html www/index.html
npx cap add android && npx cap add ios
npx cap sync && npx cap open android
```

包成原生後會多拿到幾樣網頁做不到的東西：

- **背景定位**（螢幕關閉、切到別的 App 仍持續警示）— 這是原生版最大的價值
- 原生 TTS，語音比瀏覽器穩定
- 沒有 CORS 限制
- 離線圖資

## 已驗證的行為

用 Playwright 跑過自動化測試，以下都確認正確：

- 距離與方位計算（Haversine / bearing）
- 「南北雙向 / 東西雙向 / 北上 / 南下 / 北往南 / 東往西…」等 8 種方向字串解析
- 三級警示在正確距離觸發，語音內容正確（含「你目前 100，請減速」的超速提醒）
- 反向行駛不誤報、已通過的點不重報
- 區間測速優先於同位置的點測速
- 「只有超速才出聲」開啟時，未超速全程安靜
- 以國道資料集的真實欄位結構驗證：ZIP 自動解壓、座標與速限正確解析、「區間超速」自動標記為區間測速
- 多來源累加、跨來源去重、同名來源取代、單一來源移除、全部清除還原
- 國道區間測速點的三級警示與超速播報（雪隧情境）
- CSV 匯入會濾掉壞資料列、台灣範圍外的座標，以及 ZIP 內的 __MACOSX 雜項
- 樁號解析（「國道1號南下 47.5K」「台61線60.1公里處」「台9線117k+772m」→ 117.772）
- 樁號推算：校正後往南開 2 km → 52.0K、往北 500 m → 49.5K
- 樁號快選清單依車速伸縮（時速 100 → 到 51.7K；時速 30 → 到 51.0K），選中的樁號換算回座標誤差 0 m
- 警示距離：時速 100/110 的國道都精準等於 90 秒；塞車縮到下限；一般道路 500 m
- 高速掉落物 2500 m 起三級遞減、一般道路 500 m 起
- 對向車道不誤報、已通過的不重報、過期事件不警示
- 一鍵通報位置往回退 69 m 且在後方、復原鈕可用；兩顆快捷鈕分別產生「事故」與「掉落物」，尺寸 70 / 84 / 46 px 有明顯區別
- 「其他類型」選單 9 項行為：開啟、倒數條、3 秒仍開著、6.6 秒自動收起、碰觸重新計時、重新計時後仍會關、點外面收起、`e.target` 不是 Element 時不爆炸、選取後通報並關閉
- ETL 的 HTML 表格解析：忽略沒有座標的表格、合併多張表、`<br>` 轉空白、壞資料列丟棄
- EXIF：正常 JPEG 解出 24.925/121.29083、南半球西半球正負號、非 JPEG 與無 EXIF 都給明確錯誤
- 後端 52 項測試全過（見 backend/README.md）
- 原生橋接（用模擬的 Capacitor）：正確走背景定位而非網頁定位、watcher 參數正確、位置回呼進得來、語音走原生 TTS 且 `lang=zh-TW` / `category=playback`、權限被拒時給出「改成永遠允許」的可行動提示
- 回報人數：自己回報 1 人 → 兩人在同處回報 → 變 3 人；按「我也看到了」→ 4 人且按鈕消失；兩票「已清掉了」→ 從清單消失
- 語音在 2 人以上唸出人數：「前方2.5公里，4人回報，注意掉落物」
- 區間起訖解析：6 個內建區間有 5 個解析出長度，132 個一般點零誤判；`竹47-1線`、`宜18-2線`這類含連字號的名稱不會被誤配

## 定位品質：這個 App 需要真正的 GPS

實地測試（筆電放在車上）發現一件重要的事：**筆電與桌機沒有 GPS 晶片**，瀏覽器改用 Wi-Fi / IP 推估位置，特徵是：

| | 手機（有 GPS） | 筆電（Wi-Fi 定位） |
|---|---|---|
| 精度 | ±5～15 公尺 | **±300～3000 公尺** |
| 更新頻率 | 每秒 1 次 | **每 10～30 秒 1 次，有時整個凍住** |
| `coords.speed` | 有 | **null** |
| `coords.heading` | 有 | **null** |

時速 100 每 20 秒就是 **556 公尺** —— 比整個第一級警示窗（600 公尺）還寬，一步就跨過去。這不是程式的 bug，是取樣本身就沒有那些資訊，軟體救不回來。

v1.2 針對這件事做了四件事：

1. **明講**。判定為不堪用時，畫面上直接顯示紅色警告與具體原因（誤差多少、多久更新一次），不再安靜地假裝在工作 —— 那是最糟的壞法。
2. **不顯示假車速**。推算不可信時顯示 `--`，也不會唸出「你目前 XXX，請減速」。以前一次定位跳動就會算出 14004 km/h，還拿它去決定警示距離，連帶噴出別條路的誤報。
3. **更新間隔補償**。警示窗會自動撐開到涵蓋「一次更新會走的距離」。定位正常時補償僅約 28 公尺等於沒作用；定位很慢時才明顯放寬。實測：20 秒更新一次的情況，從「開到 113 公尺才響一次」變成「670 公尺就先預告」。
4. **線段掃描**。改成計算「上一個定位點到這個定位點的線段」離測速點多近，而不是只看當下這一點。只要真的開過去，中間漏掉幾筆定位也至少會響一次。這對真手機在隧道口、訊號中斷時同樣有效。

**結論：請用手機測試。** 筆電可以拿來開發與看畫面，但不能用來驗證警示是否準確。

## 已知限制

- **筆電／桌機不能用來實測**：沒有 GPS 晶片，Wi-Fi 定位的精度與更新率都不足以做行車警示。App 會偵測並明講，但無法補救。
- 網頁版**無法背景執行**：切到別的 App 或關螢幕就停止警示。用 `mobile/` 打包成 App 可解決（橋接層已寫好），但**原生建置我沒有實機驗證過** —— 容器裡沒有 Android SDK 與 Xcode。
- iOS Safari **不支援震動 API**。
- 地圖圖磚需要網路，隧道內會空白 —— 這也是為什麼保留了不需網路的雷達視圖。
- 移動式測速、臨檢完全依賴使用者回報。
- 樁號換算是沿目前航向直線外推，彎道多的路段（例如國3山區）誤差會變大；建議每隔幾公里用里程牌重新校正一次。
- 樁號錨點來自已匯入的國道測速點名稱，**沒匯入國道資料就只能手動校正**。
- 背景定位很耗電。已有靜止自動省電，但**省電模式下仍會維持低頻定位**（才能偵測重新開動），長途使用仍建議插充電線。
- 區間測速的**進入點是用單一座標判斷**（開放資料只給一個點），中途從交流道切入切出可能算不準；走過頭 1.8 倍長度會自動放棄該次計算，也可以手動按「取消這次計算」。
- 前方測速點清單**載入路網後會沿著路算**；沒載入路網時仍是航向錐形，彎道會漏列。
- 路網只涵蓋國道與快速道路（預設），市區道路仍走錐形判斷。要涵蓋省道得加 `--classes primary`，檔案會大很多。
- 臺南的座標是 geocoding 推算值，不是官方公布值；`geocode_method=nominatim` 那些可能落在路段中間而非實際設置點。
- 沙箱環境（例如某些預覽器）不允許 localStorage 時，設定與回報只在本次開啟期間有效，App 會提示。
