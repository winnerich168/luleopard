# 鹿豹 · 路況回報後端

一支 Cloudflare Worker + 一個 KV namespace。**免費方案就夠跑**，不用信用卡、不用管伺服器。

沒有這支後端，回報只會留在自己手機裡 —— 對別人完全沒有預警作用，也就失去意義。

---

## 部署（約 5 分鐘）

```bash
cd backend
npm i -D wrangler

# 1. 建立 KV
npx wrangler kv namespace create HAZARDS
npx wrangler kv namespace create HAZARDS --preview
#    把印出來的兩個 id 貼進 wrangler.toml

# 2. 部署
npx wrangler deploy
```

部署完會拿到一個網址，例如
`https://luleopard-hazards.你的帳號.workers.dev`

把它填進 App 的「回報 → 共享回報」欄位就完成了。

### 本機開發

```bash
npx wrangler dev            # 起在 localhost:8787
node test_worker.mjs        # 純邏輯測試，不需要 wrangler 也不需要網路
```

## API

| 方法 | 路徑 | 說明 |
|---|---|---|
| `GET` | `/hazards?lat=&lon=&r=8000` | 查附近有效事件，回傳含 `dist`，由近而遠 |
| `POST` | `/report` | 新增回報。附近 150 公尺內有同類事件會自動併成「確認」 |
| `POST` | `/hazards/:id/confirm` | 我也看到了 → 可信度 +1，並延長存活時間 |
| `POST` | `/hazards/:id/clear` | 已經清掉了 → 累積 2 票就從清單消失 |
| `POST` | `/hazards/:id/retract` | **撤銷自己的回報**（我按錯了）→ 立刻刪除。只有原回報裝置能用，別人打會回 403 |
| `POST` | `/hazards/:id/probe` | **被動車流探針**。body 只有 `{lat,lon,slowed}` |
| `POST` | `/reconcile` | 手動觸發官方對帳（需 `Authorization: Bearer <ADMIN_TOKEN>`），平常由 cron 每 10 分鐘自動跑 |
| `GET` | `/stats` | 目前存了幾筆 |

`POST /report` 的 body：

```json
{
  "lat": 25.048611, "lon": 121.290833,
  "type": "掉落物",
  "roadClass": "國道", "road": "國1", "dir": "南下", "km": 47.5,
  "lane": "外側車道", "note": "輪胎皮",
  "brg": 180,
  "device": "隨機產生的匿名代號"
}
```

`brg` 是回報當下的行進方位角。**這個欄位很重要** —— 後端與 App 都用它來排除對向車道的事件，沒有它的話，南下的掉落物會去吵北上的車。

## 設計取捨

**空間索引用 KV key 前綴，不用資料庫。**
key 格式 `h:<網格>:<id>`，網格是 0.05°（約 5.5 公里）。查詢時掃周圍幾格再用 Haversine 精算距離。省掉一整套 PostGIS，免費方案就撐得住。

**自動過期，不需要清理排程。**
寫入時就設定 KV 的 `expirationTtl`，時間到自己消失。各類型時效不同：

| 類型 | 存活 | 為什麼 |
|---|---|---|
| 掉落物、事故 | 2 小時 | 通常這段時間內會被清掉或處理完 |
| 車輛故障、動物 | 1 小時 | |
| 塞車 | 45 分鐘 | 車流變化快，久了就不準 |
| 臨檢 | 3 小時 | |
| 積水 | 6 小時 | |
| 施工 | 12 小時 | |
| 路面坑洞 | 24 小時 | 通常要等養護單位排程 |

有人再次回報或按確認時會**延長**存活時間 —— 東西還在，警示就繼續。

**近距離同類自動合併。**
150 公尺內、方向相近的同類回報不會產生新的點，而是幫既有那筆 +1 確認。避免十個人經過同一個輪胎皮就長出十個圖示。方向差超過 60° 則視為對向車道的另一件事。

**防灌水：** 同一個匿名裝置代號 20 秒內只能回報一次。

**隱私：** 不存照片、不存帳號、不存軌跡。裝置代號是客戶端隨機產生的字串，只用來做上面那個冷卻，回傳給其他人的資料裡不包含它。

## 過期事件的自動下架

固定 TTL 不夠。事故 10:00 回報、10:35 排除，TTL 2 小時的話它會再吵 85 分鐘。所以除了 TTL 之外還有三層：

### 1. 置信度分數（取代單純的 TTL）

```
score = (2 + confirms) × 0.5^(age/半衰期) × 0.72^(沒減速探針) × 1.18^(有減速探針)
```

`score < 0.40` 就不再回傳給任何人（`isAlive` 判定），KV 的 TTL 只當最後的兜底。半衰期依類型：塞車 15 分、車輛故障／動物 20 分、事故 25 分、掉落物 45 分、臨檢 60 分、積水 3 小時、施工 4 小時、坑洞 12 小時。

結果：**沒有任何人動它的事故，35 分鐘後就從語音降級成靜音顯示，1 小時後完全消失。**

### 2. 被動車流探針 `POST /hazards/:id/probe`

App 端偵測「開過事件時有沒有掉速」，只送一個布林值：

```json
{ "lat": 24.30, "lon": 121.10, "slowed": false }
```

沒有速度、沒有回報者座標、沒有裝置代號 —— **後端無從得知是誰經過的**。每筆探針乘上 0.72（沒減速）或 1.18（有減速，上限 3 倍），最多累積 40 筆。3~4 台車開過去沒減速，20 分鐘內就會自動下架。

### 3. 撤銷 `POST /hazards/:id/retract`

按錯的人自己撤回，立刻刪除，不用等投票。後端比對 `h.by === device.slice(0,12)`，**不是原回報者一律 403** —— 否則一個人就能把全台灣的回報刪光。

### 4. 官方對帳（cron，每 10 分鐘）

`wrangler.toml` 的 `crons = ["*/10 * * * *"]` 觸發 `scheduled()` → `reconcile(env)`：抓 TDX 即時事件，與使用者回報比對 **500 公尺內 + 同類型 + 方位角夾角 ≤ 90°**。官方說結束 → 直接刪除；官方說進行中 → 分數給 1.2 的下限，不讓它提早消失。

金鑰用 secret 存：

```bash
npx wrangler secret put TDX_ID
npx wrangler secret put TDX_SECRET
npx wrangler secret put ADMIN_TOKEN     # 保護手動觸發的 /reconcile
```

沒設金鑰時 cron 會明確略過（log 一行後結束），不會讓整個 Worker 掛掉。

**這四層都不需要有人顧後台。**

## 已驗證

`node test_worker.mjs` 共 52 項，全部通過。用一個假的 KV 直接跑 worker，不需要 wrangler、不需要網路：

- CORS preflight、未知路徑 404、缺參數 400
- 新增回報、保留樁號、回應不外流裝置代號
- 同裝置冷卻 429、台灣範圍外拒收、控制字元清理
- 150 公尺內同類自動併成確認、對向不併、不同類型不併
- 查詢由近而遠、遠處查不到、半徑生效
- confirm 累加、兩票 clear 後移除、對已移除的事件回 404
- 過期事件不回傳、各類型 TTL 正確
- 沒綁 KV 時明確報錯而不是靜默壞掉
- 置信度衰減曲線：事故 25 分掉一半、35 分低於出聲門檻、60 分低於顯示門檻
- 探針：沒減速的乘 0.72、有減速的乘 1.18（上限 3 倍）、超過 40 筆不再累積
- **4 台車沒減速 → 20 分鐘就下架**
- 撤銷：原回報者可撤、**別人不能撤銷我的回報（403）**、已撤銷的不再回傳
- 官方對帳：500 公尺內同類同向才配對、官方說結束就刪除、官方說進行中就給分數下限、**未設金鑰時明確略過而不是爆炸**

## 免費額度夠用嗎

Cloudflare 免費方案：Workers 每天 10 萬次請求、KV 每天 10 萬次讀 / **1000 次寫**。

寫入是瓶頸。每筆回報 = 2 次寫（事件 + 冷卻），所以**每天約 500 筆回報**。以初期使用者規模綽綽有餘；真的成長到會撞上限時，改用 Cloudflare D1（SQLite）就好，程式結構不用大改。

讀取方面，App 預設每 3 分鐘拉一次周邊 15 公里，一位使用者連續開車 1 小時約 20 次查詢，每次掃數十個 key —— 這是目前最花額度的地方。若使用者變多，可在 Worker 前面加一層 `caches.default`，把同一網格的查詢結果快取 30 秒。
